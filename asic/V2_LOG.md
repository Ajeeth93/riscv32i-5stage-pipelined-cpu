### Heat map (met1, VPWR) — docs/img/irdrop_met1_vpwr.png
- PDN: 3 vertical met4 straps, 3 horizontal met5 straps.
- Horizontal bands = one met1 rail per row; busier rows show more drop.
- Lowest drop directly under the met4 straps.

  Watch the right edge first if the grid is made sparser; rebalance the strap offset/pitch if needed.

### 2b. Timing GLS with SDF — blocked in Icarus
- Without -DFUNCTIONAL the sky130 timing models need power pins (error: no wire VPWR) and,
  more importantly, drive their flops through D_delayed / CLK_delayed, which are generated by
  $setuphold. Icarus does not support timing checks, so these signals are never driven:
  every flop would see floating inputs.
- Conclusion: Icarus is valid for functional GLS only with these models.
- Timing evidence for sky130: STA sign-off clean at 9 corners + functional GLS PASS.
- Solved with CVC and a patched cell library (see 2c). Xcelium on Cadence later for full checks.


### 2c. Timing GLS with SDF in CVC — PASS at 40 MHz
- Simulator: open-source CVC (OSS_CVC 7.00b). Power-aware netlist (final/pnl), VPWR/VGND tied with supply1/supply0.
- Problem: the sky130 timing models drive their flops through X_delayed copies that only $setuphold/$recrem
  create; CVC (like Icarus) ignores that feature, so every flop saw undriven inputs and PC = X.
- Fix: patch_delayed.py adds `assign X_delayed = X;` only for names inside $setuphold/$recrem
  (a first version also hit internal signals such as SCE_gate_delayed and failed). Patched copy; PDK file untouched.
- SDF: all IOPATH/INTERCONNECT delays annotated. 66 RECOVERY/REMOVAL entries on dfrtp_2 have no matching
  check in the cell model (covered by STA).
- Lesson: piping a running simulation into `head` kills it (SIGPIPE). Let it finish, then filter the log.

## 3. Branch-comparator optimisation

### Before (STA, max_ss_100C_1v60, 25 ns)
- Worst path: Rs2E → forwarding detection (4.3 ns) → forwarding + ALUSrc mux (1.8) → ALU subtract (4.4)
  → 32-bit zero detect (6.6) → PCSrcE + fanout (2.0) → next-PC mux → PC register. Arrival 23.08 ns, slack +3.13 ns.
- Agrees with CVC timing simulation (first violations at PC / ID/EX flops at 18 ns).

### Change
- New module RISC_V_Pipeline_BranchComparator: EqE = (SrcAE == WriteDataE) on the forwarded operands,
  in parallel with the ALU. PCSrcE = (BranchE & EqE) | JumpE. ZeroE left unconnected → synthesis removes it.
- Core supports only beq, so equality is the whole branch decision.
- RTL simulation: PASS, 25 cycles, CPI 1.316, unchanged (the branch is still decided in Execute).
